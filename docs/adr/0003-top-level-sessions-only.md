# 只作用于顶层会话, 子代理不进范围

DSH 里每个子代理、workflow 子任务和 Ralph 每一轮都是**独立的 agent 与独立会话**,各有自己的上下文窗口。让插件在这些会话里也生效,意味着每一个子代理的请求都会多一段提示词、每一条大输出都会多一条提醒,而子代理数量在 workflow 与 Ralph 下可以很多。

因此插件只作用于**顶层会话**:所有入口在 `session.header.delegationDepth > 0` 时直接返回 —— 这包括提示词段落(渲染为空字符串,被 DSH 过滤)与两种提醒。判断依据是会话头部持久化的 `delegationDepth`(文档原话:absent (zero) for a top-level session, parent depth + 1 for a subagent child),而不是运行时状态,所以重启与恢复后依然成立。

**刻意留下的残留**:`context_status` 工具是全局注册的,所以子代理的工具表里仍然会有它。要把它从子代理的工具表里去掉,就得改成按 agent 注册工具,复杂度明显上升;而工具表里的那一项成本**无论拒不拒绝都已经付了**,拒绝执行只买到口径统一,买不到省 token。所以子代理调用它就正常回答:能读到真实数据,总比读到一句拒绝更有用。
