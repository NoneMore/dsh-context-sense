# 系统提示词只承载常量,实时状态走工具与运行时提醒

需求要求把总上下文窗口与压缩阈值注入系统提示词,并在越过阈值或工具输出过大时提醒模型。但 DSH 的提示词注入是**追加式**的:路由声明 `systemPromptUpdate: "in-history"`,因此改变的提示词不会重写前导 `system` 消息,而是追加一条新的 `system/message`;运行时上下文快照(`systemPrompt.context`)同样按整份快照文本去重,只在文本真的变化时追加。所以每轮变化的数字**不会**破坏 provider 前缀缓存,但会让会话**单调增长** —— 每轮追加一份完整的提示词副本,并在之后每一次请求里重复计费。这正是"把实时用量写进系统提示词"看起来便宜、实际很贵的原因。

因此注入系统提示词的只有两个常量 —— 上下文窗口与压缩阈值 —— 外加一句固定指引,告诉模型可以用查询工具获取实时状态。所有随轮次变化的信息(当前用量、分类明细、是否越过预警线)一律不进入系统提示词:需求 2 交给模型按需调用的查询工具,需求 3、4 交给运行时注入的短提醒。

代价是模型不再无条件知道"现在用了多少",必须自己调用工具。这既是需求 2 存在的原因,也意味着那句静态指引必须明确告诉模型**何时**该查 —— 否则工具永远不被调用,前两条需求互相抵消。
